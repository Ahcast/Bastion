# Convertir un proceso a cotización

Decisión nueva confirmada por el usuario el 23 de octubre de 2026; no se presenta como comportamiento Legacy.

En el detalle desplegado de un proceso vigente aparece **Convertir a cotización**. Requiere Procesos/consulta/ver y Cotizaciones/documentos/ver y editar, con ambos módulos habilitados. Antes de abrir el editor se vuelve a consultar el detalle autorizado; un proceso vencido, eliminado o inaccesible no inicia la conversión. No se crea nada en la base al pulsar: se abre un borrador editable y el usuario utiliza Guardar cotización normalmente. Evita crear documentos incompletos o duplicados por un doble clic.

Mapeo: `entidad → client_name` manual, sin crear ni vincular por similitud un cliente del catálogo; `expediente → order_number` (referencia). El usuario puede seleccionar posteriormente un cliente existente. No se infieren RTN ni correo de la entidad. Fecha, vigencia, impuestos y demás valores usan los valores iniciales existentes del editor. Los precios quedan en cero para completarlos.

Corrección confirmada el 23 de octubre: los ítems se obtienen exclusivamente de `items`, la lista individual analizada por IA de Scout (texto numerado o JSON de textos anterior). Cada entrada produce una línea de cotización. No se usan `descripcion` ni `items_fuente`: una fila original puede agrupar muchos productos, y el CSV real tiene código/categoría/especificaciones/cantidad, no el orden supuesto inicialmente. Una lista vacía da un error claro; no se reemplaza por una descripción genérica.

La cantidad se extrae del inicio de cada ítem: `150 unidades de relé`, `02 juegos de ballestas`, `1 × café` o `Cantidad: 1; UAV`. Se retira el prefijo numérico de la descripción y se conservan unidades, modelos, medidas y especificaciones restantes. No se toman cantidades de otra fila ni números de orden, modelos, dimensiones o números internos como cantidades. Números sin signo, hasta 12 enteros y 4 decimales; ceros iniciales normalizados. Comas en grupos de tres son separadores de miles (p. ej. `11,700 → 11700`); una coma decimal distinta se normaliza a punto. Texto sin una cantidad inicial verificable conserva su descripción y deja la cantidad vacía para completar, sin inventar 1. No se dividen frases por comas, porque pueden ser especificaciones. No se recortan ítems ni datos para pasar los límites existentes de Cotizaciones (200 líneas, descripción 3000, cliente 255, referencia 100).

El editor presenta una franja informativa: **«El listado de ítems se generó automáticamente. Revisa siempre el proceso original antes de cotizar.»** Incluye enlace al original cuando su URL es HTTP(S), sin credenciales. Se muestra como texto escapado y región `status` de anuncio cortés, sin modal, confirmación, cuenta regresiva, toma de foco ni botón obligatorio. Se mantiene durante esa edición, incluso después de guardar. No se incorpora al PDF, correo, notas privadas ni datos comerciales; al cerrar la edición termina este recordatorio de conversión. Cuando faltan cantidades, la misma franja lo indica. La validación normal del formulario exige completarlas antes de guardar.

No se agregan endpoints, permisos, ajustes ni acceso directo entre bases de módulos. Se reutilizan el detalle autorizado de Procesos y el alta/cálculo de Cotizaciones, con sesión, CSRF, validación Rust, idempotencia y auditoría existentes. Deshabilitar el destino o retirar permisos antes del guardado hace que el servidor rechace la escritura. El traspaso es estado transitorio de la interfaz y se limpia al cerrar sesión o abandonar el módulo mediante la navegación habitual. Publicación primero en GitHub; despliegue separado.
